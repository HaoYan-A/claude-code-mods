# subagent-effort 实现原理

这个模组的代码只有 60 多行（[`hooks/register.ts`](hooks/register.ts)），核心思路是：**一个子代理从"被派出"到"向模型发请求"的途中，有四个时刻 Claude Code 会先停下来问一声模组，模组就在这四个时刻分别动一下手。**

本文对应 Claude Code 2.1.287、模组 0.2.1。

## 要解决的问题

主会话派子代理靠的是 `Agent` 工具，它有两个限制：

- `model` 参数只认 `sonnet`、`opus`、`haiku`、`fable` 四个简称，写 `gpt-6` 会被当成非法参数直接拒绝
- 根本没有思考等级这个参数，子代理只能跟着定义文件或主会话走

## 模组怎么"插手"

模组就是一段代码，里面用 `on(时刻, 处理函数)` 登记：到了某个时刻，Claude Code 先把这件事交给这个函数处理。函数拿到三样东西：

- `$`：能调用的各种能力，比如写对话记录、弹提示
- `e`：这件事的内容，比如工具调用的参数、要发给模型的请求
- `next(e)`：交还给 Claude Code，让它接着往下做

函数可以原样交还，可以改了内容再交还，也可以直接拒绝。

## 一个子代理经过的四个时刻

```
主会话决定派子代理：Agent(model: "gpt-6", effort: "low", ...)
        │
  ① tool.call   工具检查参数之前
        │      取走 gpt-6 和 low，记进小本子 A（键是这次调用的编号）
        │      剩下的参数交给工具检查 → 都合法，通过
        ▼
  ② agent.spawn 子代理启动之前
        │      用调用编号从本子 A 取出 gpt-6，填回模型
        │      启动后拿到子代理编号，把 low 记进小本子 B（键是子代理编号）
        │      在对话记录写一行灰字：Subagent general-purpose → gpt-6 · low
        ▼
  ③ turn.step   子代理每一次向模型发请求之前（可能发很多次）
        │      用子代理编号查本子 B，查到 low，就把这次请求的档位改成 low
        ▼
     请求发出：model=gpt-6, effort=low
```

还有第 ④ 个时刻 `tool.describe`：主会话第一次看到 `Agent` 工具说明时，模组在说明末尾追加一段话，告诉它 `model` 可以填任意模型名，另外可以加一个 `effort` 参数。主会话就是靠这段话学会这么填的。

对应代码：

| 时刻 | 位置 | 做什么 |
| --- | --- | --- |
| ④ `tool.describe` | `register.ts:26` | 在 `Agent` 工具说明末尾追加约定（文字在第 8 行的 `USAGE`） |
| ① `tool.call` | `register.ts:32` | 取走自定义模型名和 `effort`，记进本子 A；档位不在五档内就拒绝 |
| ② `agent.spawn` | `register.ts:47` | 填回模型，记下"子代理编号 → 档位"，写灰字 |
| ③ `turn.step` | `register.ts:58` | 按子代理编号改写每一次请求的档位 |
| `session.start` | `register.ts:21` | 模组在会话中途加载时，让 `Agent` 工具说明重新生成 |

两个小本子分别是第 15 行的 `asked`（本子 A）和第 17 行的 `effortOf`（本子 B）。

## 几个关键设计

**为什么要先"取走"再"填回"？**

第 ① 步发生在工具检查参数之前。如果不先取走，`gpt-6` 和 `effort` 都会被当成非法参数拒绝。第 ② 步这个时刻允许填任意完整的模型名，所以在这里填回去。这一招学自 [cc-multi-cli-plugin](https://github.com/greenpolo/cc-multi-cli-plugin)。

**为什么要两个小本子？**

三个时刻用的"身份证"不一样：

- 第 ① 步只知道"这次调用的编号"
- 第 ③ 步只知道"子代理的编号"
- 第 ② 步两个编号都知道，所以由它负责把两边接起来

本子 A 只在这次调用期间有用，调用结束就清掉。本子 B 要一直保留，因为子代理后面还会发很多次请求，它也可能被继续派活。

**为什么思考等级要每次请求都改，而不是启动时设一次？**

子代理启动那一刻，Claude Code 只开放了改模型，没开放改档位。所以只能在它每次发请求之前都改一遍。

**校验**

模型名不检查：写错的话 Claude Code 1 秒内就会报"模型不存在"，主会话看到后能重试。档位只认五档，写错了在第 ① 步直接退回。

## 怎么验证的

- **自动测试**：写了一个"假引擎"，模拟 `Agent` 工具收到调用后启动子代理、子代理发请求的全过程，检查每一步的参数有没有被正确取走、填回、改写。用 `claude plugin test plugins/subagent-effort` 运行。
- **实际请求核对**：在本机临时起一个转发站，让测试会话的请求先经过它，再转给真正的网关，它把每条请求实际带的模型和档位记下来。这样确认的是"真正发出去的是什么"，而不是子代理自己说的。结果见 [README 的实测一节](README.md#实测)。

## 已知限制

- `fork` 类型的子代理，Claude Code 规定它永远跟主会话用同一个模型，第 ② 步填模型对它无效；思考等级仍然能改
- 本子 B 存在模组的内存里。模组如果在子代理运行途中被重新加载，这个子代理剩下的请求会回到默认档位
- 工具说明只在会话开始时生成一次。会话进行到一半才装上模组的话，要到下一个新会话，主会话才会知道这个约定
